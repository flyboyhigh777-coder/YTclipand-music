# rules.md — правила проекта YTclip&music

Единый свод правил: как устроен проект, какой инструмент за что отвечает,
где лежат файлы и как добавлять новое. **Любой новый файл сначала
прописывается здесь**, в разделе «Карта файлов».

---

## 1. Разделение ответственности (главное правило)

Каждый инструмент делает ровно одну работу и не лезет в чужую:

| Инструмент | Зона ответственности | Чего НЕ делает |
|---|---|---|
| **ffmpeg** | декодирование, нарезка трека на фрагменты, сведение видео+звука, финальный экспорт, нормализация громкости | не рисует анимацию |
| **Whisper** | речь → текст со таймкодами слов (`word_timestamps`) | не решает, что показывать на экране |
| **анализ (numpy)** | темп, биты, доли такта, энергия, где вокал, где припев/хук | не рисует и не распознаёт слова |
| **Remotion** | вся анимация и графика: от простых титров до 3D-сцен | не режет звук, не считает темп |

Данные между ними ходят **только через JSON** (`clip.json`). Это значит: любой
слой можно переписать, не трогая остальные.

```
трек.mp3 ─┬─> ffmpeg ──────> фрагмент.wav/aac
          ├─> Whisper ─────> слова + таймкоды ─┐
          ├─> анализ ───────> биты, хуки ──────┼─> clip.json ─> Remotion ─> reel.mp4
          └─> обложка.jpg ─> палитра ──────────┘
```

## 2. Правила таймкодов и субтитров

1. **Время всегда в секундах, float, от начала исходного трека.** Никаких
   кадров и никаких «мм:сс» внутри кода — только на входе/выходе.
2. Таймкоды внутри клипа пересчитываются относительно начала клипа **один раз**,
   при сборке `clip.json`. Дальше Remotion работает только с локальным временем.
3. **Субтитр появляется в момент произношения слова**, не раньше. Допуск —
   не больше 80 мс.
4. Приоритет источников тайминга (от точного к грубому):
   1. `.lrc` с таймкодами слов (enhanced LRC) — используется как есть;
   2. Whisper с `word_timestamps=True`, слова сверены с официальным текстом;
   3. `.lrc`/`.srt` с таймкодами строк — слова раскидываются внутри строки;
   4. голый `.txt` — строки раскидываются по найденным вокальным фразам.
5. **Официальный текст важнее распознанного.** Whisper слышит с ошибками;
   написание всегда берётся из вашего текста, от Whisper — только время.
6. Любой тайминг можно выгрузить в `.lrc`, поправить руками и вернуть обратно —
   это штатный путь, а не костыль.

## 3. Правила видео для Reels / TikTok / Shorts

1. **Формат:** 1080×1920 (9:16), 30 fps, H.264 high, **yuv420p** (не `yuvj420p`:
   полнодиапазонный цвет выцветает на части плееров), bt709, `+faststart`,
   звук AAC 192 kbps 48 kHz стерео. Проверяется командой `ytclip check`.
2. **Длина:** 15–30 с. По умолчанию 22 с.
3. **Безопасные зоны** (там не должно быть текста и важной графики):
   - сверху 180 px,
   - снизу 320 px (подписи и кнопки TikTok),
   - справа 140 px (колонка кнопок).
   Субтитры ставим в полосе y ≈ 1150–1500.
4. **Клип начинается с доли такта** (downbeat) и по возможности не разрезает
   строку текста посередине.
5. **Первые 1.5 секунды — это хук.** Никаких долгих интро и пустых логотипов.
6. Громкость сводится через `alimiter`, пик −0.3 dB; фейд на выходе 0.25 с.

## 4. Правила графики (стиль обложки)

0. **Логотип и обложка неприкосновенны.** Они используются ровно такими, какими
   их прислала группа: не перерисовывать, не перекрашивать, не менять шрифт,
   не «улучшать», не генерировать свои варианты. Разрешено только: размещать
   в кадре, масштабировать с сохранением пропорций, двигать, затемнять/осветлять
   кадр вокруг. Если нужен логотип на тёмном фоне — берётся присланный
   светлый/прозрачный вариант, а не перекрашенный.

1. Палитра **всегда берётся из обложки** (`ytclip/palette.py`), а не
   задаётся руками. Руками — только если явно передан `--palette`.
2. Роли цветов: `bg`/`bg2` — фон, `accent` — подсветка активного слова и
   акценты графики, `accent2` — второй акцент, `text` — читаемый текст.
3. **Контраст текста обязателен:** если подложка светлая — тёмный текст, и
   наоборот. Проверяем по яркости (`luma`), а не на глаз.
4. Движение привязано к музыке: пульс — к битам, смена сцены — к границе
   такта, яркость/масштаб — к энергии. **Анимация «просто по таймеру»
   запрещена** там, где есть данные анализа.
5. Шрифты: Inter / Inter Display — заголовки и машинопись; JetBrains Mono —
   технические подписи; Caveat — рукописный синий маркер. Caveat поставляется
   с проектом (`@fontsource/caveat`), чтобы рендер не зависел от сети.
6. Один клип = один визуальный приём. Не мешать пять эффектов в кучу.
7. **Рисованное — только на бумаге.** Человечки и символы рисуются синим
   маркером на полях страницы и никогда не накладываются поверх обложки или
   фотографии.
8. **Не увеличивать картинку сверх её разрешения.** Перед приближением
   считается, сколько в источнике настоящих пикселей; апскейл больше 2× даёт
   мыло и запрещён (`safeZoom` в `remotion/src/lib/photo.ts`).

## 4a. Фирменный язык th3rd.

Снят с обложки альбома «ЕСЛИ ХОЧЕШЬ СЕРЬЁЗНО» и зафиксирован в
`assets/brand/th3rd.json` и `remotion/src/lib/brand.ts`:

| Роль | Цвет | Откуда |
|---|---|---|
| бумага | `#E2DED5` | фон обложки |
| текст | `#1A1A1E` | чёрный лого |
| красный акцент | `#B33E2D` | точка в лого и обведённый круг |
| синий маркер | `#3A4079` | рукописные пометки |

Приёмы: тёплая бумага с зерном, поляроид на скотче, машинопись на обрывках
бумаги, синий рукописный маркер, лёгкое дрожание камеры (как будто снимают
с рук), рисованные символы на полях.

Чего не делаем: неон, глянец, резкие градиенты, свечение, глитч-эффекты.

## 5. Правила файлов и папок

1. **Исходники пользователя** (треки, обложки, тексты) — в `input/<slug-трека>/`.
   Эта папка в `.gitignore`: чужую музыку в репозиторий не коммитим.
2. **Результаты** — в `out/<slug-трека>/`. Тоже не коммитим.
3. **Промежуточные данные** (анализ, JSON, вырезанные wav) — в
   `work/<slug-трека>/`. Не коммитим.
4. Имя файла результата: `<slug>__<шаблон>__<номер>.mp4`,
   например `nochnoy-reys__cover-pulse__01.mp4`.
5. Ничего не перезаписываем молча: если файл есть, добавляем суффикс или
   требуем `--force`.
6. В git идут только код, правила, документация и демо-ассеты (синтетические).

---

## 6. Правила кода

1. Python 3.11+, зависимости по минимуму: `numpy`, `Pillow` обязательны;
   `faster-whisper` — опционально (только для распознавания).
2. Анализ звука — на numpy, без librosa (чтобы ставилось где угодно).
3. Внешние вызовы (`ffmpeg`, `npx remotion`) — только через обёртки в
   `ytclip/ffmpeg_io.py` и `ytclip/remotion_bridge.py`. Прямых `subprocess`
   в других модулях быть не должно.
4. Код и комментарии — по-английски; документация и тексты для человека —
   по-русски.
5. Каждый модуль можно запустить и проверить отдельно. Любая новая
   возможность добавляется как подкоманда в `ytclip/cli.py`.
6. Никаких «тихих» падений: если нет ffmpeg, модели Whisper или Node —
   говорим прямо, что именно отсутствует и как поставить.

---

## 7. Правила работы с Remotion

1. Композиции получают данные **только через props** (`clip.json`), внутри
   компонентов ничего не захардкожено.
2. Один файл = одна композиция (шаблон). Новый шаблон регистрируется в
   `remotion/src/Root.tsx` и прописывается здесь.
3. 3D-сцены — через `@remotion/three` (`ThreeCanvas`), анимация кадра
   считается от `useCurrentFrame()`, а не от реального времени.
4. Рендер — всегда headless Chromium, путь задаётся переменной
   `REMOTION_BROWSER_EXECUTABLE` (в этом окружении
   `/opt/pw-browsers/chromium`), с флагами `--headless --no-sandbox`.
5. Звук в композицию не вшиваем: Remotion рисует картинку, звук подмешивает
   ffmpeg на финальном шаге. Исключение — предпросмотр в Studio.

## 8. Карта файлов

### Код — Python (анализ и оркестрация)

| Файл | Назначение |
|---|---|
| `ytclip/__init__.py` | версия пакета, публичный импорт |
| `ytclip/ffmpeg_io.py` | единственное место, где вызывается ffmpeg/ffprobe: декод в numpy, нарезка, сборка видео, извлечение встроенной обложки |
| `ytclip/analysis.py` | DSP на numpy: спектрограмма, спектральный поток, темп, трекинг битов, доли такта, энергия по полосам, детектор вокала, вокальные фразы |
| `ytclip/hooks.py` | поиск самых цепляющих фрагментов: громкость + повторяемость (припев) + вокал + эффектный вход; привязка к такту |
| `ytclip/palette.py` | палитра из обложки, роли цветов, конвертация в ASS/hex |
| `ytclip/lyrics.py` | разбор `.txt`/`.lrc`/`.srt`, слоги (рус/лат), тайминг слов, выгрузка в `.lrc` |
| `ytclip/transcribe.py` | обёртка над Whisper (`faster-whisper`): слова с таймкодами, кэш в JSON, сверка распознанного с официальным текстом |
| `ytclip/project.py` | сборка `clip.json`: нарезка, палитра, биты, слова, выбор шаблона |
| `ytclip/remotion_bridge.py` | единственное место, где вызывается `npx remotion`: рендер композиции с props |
| `ytclip/artwork.py` | находит фотографию внутри обложки-коллажа, вырезает её и увеличивает с резкостью; запоминает настоящее разрешение источника |
| `ytclip/check.py` | проверка готового клипа по чек-листу §10: формат, цвет, звук, безопасные зоны |
| `ytclip/cli.py` | командный интерфейс: `analyze`, `hooks`, `transcribe`, `align`, `reels`, `render`, `check`, `doctor` |
| `ytclip/__main__.py` | точка входа `python -m ytclip` |

## 9. Как добавить новый шаблон (чек-лист)

1. Создать `remotion/src/templates/<Имя>.tsx`, данные брать только из props.
2. Зарегистрировать композицию в `remotion/src/Root.tsx`.
3. Добавить имя шаблона в список в `ytclip/project.py`.
4. Прописать шаблон в разделе «Карта файлов» этого файла.
5. Проверить: `npm run typecheck` в `remotion/`, затем рендер одного клипа.
6. Проверить безопасные зоны (п. 3) и контраст текста (п. 4.3).

---

## 10. Что проверяем перед выдачей клипа

- [ ] 1080×1920, 30 fps, H.264 + AAC, `+faststart`
- [ ] длина 15–30 с, начало с доли такта
- [ ] субтитры попадают в слова (расхождение < 80 мс)
- [ ] текст читается и не заходит в безопасные зоны
- [ ] цвета совпадают с обложкой
- [ ] звук без клиппинга, есть фейд на выходе
- [ ] файл назван по правилу из п. 5.4
